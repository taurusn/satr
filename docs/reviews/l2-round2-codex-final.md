## New findings

- **Blocker — PAGE-1/2/3, §9.2:** The literal CSP omits `linen-kit:` from `script-src`, so linked `loom.js` cannot run; `connect-src 'none'` contradicts loading sibling JSON; “every request off-origin” contradicts the kit. **Fix:** decide whether kit JS is isolated-world injection or an allowed source, permit exact-origin local fetch if PAGE-2 promises JSON, and state the kit exception.
- **Blocker — PAGE-1/2, §9.2:** P(a) tested scheme-wide `linen-page:`, not `'self'` or random hosts. Apple registers handlers per scheme, although WebKit models origins by scheme/host/port; the handler must therefore reject every authority except the tab token. **Fix:** P(c) must test wrong-host reads, storage isolation, sibling assets and sandbox effects on both devices. [Apple API](https://developer.apple.com/documentation/webkit/wkwebviewconfiguration/seturlschemehandler%28_%3Aforurlscheme%3A%29?language=objc), [WebKit origin code](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/page/SecurityOrigin.cpp).
- **Blocker — SYNC-1, §9.3:** An unknown phone has an accepted TLS session before Allow; nothing says that session cannot send `hello`, `want` or receive manifests. **Fix:** a pairing-only state machine accepts only code/confirmation messages, sends no metadata, then closes; ordinary sync requires a new pinned session.
- **Major — PAGE-10:** Constructor-name guessing misses innocuously named APIs, changed methods, workers/worklets and test-infrastructure failure; “and the like” is untestable. **Fix:** explicit realm/API inventory, positive escape control, timeout/error fail-closed, and compatibility keyed to the exact WebKit build.
- **Major — SYNC-4:** Expiring unacknowledged tombstones after 30 days resurrects stale files on an old phone. “Switches … at once” lacks a mechanism and reader snapshot rule. **Fix:** retain until acknowledgement or rotate the manifest ID; use immutable generation directories plus an atomic current pointer, with readers pinned to one generation.
- **Major — IOS-4:** It says iPhone pages follow only PAGE-1–8, excluding capability denial, self-test and crash recovery. **Fix:** change to PAGE-1–12.
- **Major — PAGE-1/12:** WebKit, not Linen, controls process allocation; “own web content process” and “bounded by the system’s own limits” lack pass criteria. **Fix:** require configuration/data-store separation, observe PIDs without guaranteeing them, and set an explicit stress fixture and recovery threshold.
- **Major — S2:** L(a)’s “all behave” and I(a)’s absent gate violate the promised prewritten go/no-go gates. **Fix:** enumerate pairing negatives and renderer measures before running either spike.
- **Major — §11 scope:** One person still owns five new targets plus boards, pages, sync, CLI, custom blocks and three export paths. **Fix:** make 2.0 the Mac board/page/CLI vertical slice and move iPhone/link to 2.1, or remove blocks/export work from L2.

**Verdict: not approved to build S2 yet.** The spike direction is right, but P(c), L(a) and I(a) need corrected functionality/security gates first; otherwise a “go” could still certify a broken page model or an unpaired client that receives data.
