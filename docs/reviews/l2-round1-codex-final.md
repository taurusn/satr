Verdict: not implementation-ready. The research is unusually strong, but the PRD still has two security blockers and several requirements that its exit tests could pass while the product remains broken.

### Findings

- **Blocker — PAGE-1, IOS-4, §9.2:** “Cannot reach the network” is stronger than WKWebView can guarantee. The first three controls already leaked WebRTC; the fourth is a blacklist of today’s constructors. A new WebKit API, untested execution realm, or WebKit regression bypasses the promise while the probe still passes. **Fix:** either disable arbitrary scripts for untrusted pages, or describe this as tested isolation rather than a hard security boundary, fail closed on unknown OS/WebKit versions, and rerun an expanding capability audit on every OS update. See the [page spike](/Users/hatim/Developer/Satr/docs/spikes/pages/README.md:1).

- **Blocker — SYNC-1, §9.3:** Both peers cannot be pinned during the first TLS handshake because the Mac does not yet know the phone certificate. The PRD omits the required “pairing mode” in which the server temporarily accepts an unpinned client certificate. Code entropy, expiry, attempt limits and concurrent pairing races are also unspecified. **Fix:** use a random ≥128-bit QR nonce, short expiry, one active attempt, rate limits, and a transcript-bound comparison code; authenticate only the Mac during the first TLS session, then pin the phone after confirmation. Remove the unspecified TLS 1.2 fallback—otherwise it is a downgrade to the lasting QR secret the design rejects.

- **Major — PAGE-1, PAGE-8:** The four layers cover URL traffic, not host capabilities. A hostile page can request file upload, clipboard/paste or drag-and-drop data, camera/microphone/geolocation, downloads, sharing, dialogs, or external-scheme navigation. A scripted anchor may be mistaken for Hatim’s click and make Linen open another app or browser. **Fix:** specify fail-closed UI/navigation delegates denying every capability; accept external links only through an isolated-world handler that verifies `Event.isTrusted`; add tests for each capability.

- **Major — PAGE-1–3:** The literal CSP, origin model and scheme-handler allowlist are missing. It is unclear whether page files and `linen-page://kit/` share an origin, which resources may be navigated to, and what happens if rule-list compilation fails. **Fix:** give each page an unguessable origin, put the kit on a distinct origin with exact asset allowlists, send `X-Content-Type-Options: nosniff`, define the literal CSP—preferably including a tested `sandbox allow-scripts`—and refuse to open if any seal fails.

- **Major — PAGE-7:** Scripts default on, but no availability boundary exists. Infinite loops, allocation bombs and crash loops can freeze or jetsam the WebContent process, especially on iPhone. **Fix:** after one termination reopen with scripts off, isolate page views from note/board views, provide a visible stop control, and test CPU, memory and repeated-crash recovery.

- **Major — BRD-1 versus BRD-17:** JSON Canvas requires position and size, so “nodes lack positions or sizes” is invalid JSON Canvas and should enter BRD-1’s error state. Cold ELK layout for 2,000 nodes also measured 1.4 seconds, already exceeding the 1.2-second first-paint target. **Fix:** define an explicit Linen draft format accepted only by `linen layout`, or require valid positioned files in the viewer; do not auto-layout large boards during open.

- **Major — BRD-18 versus BRD-20:** Removing off-screen nodes from the DOM prevents VoiceOver and Tab from traversing the whole board as promised. **Fix:** provide a separate native/virtual accessibility tree or retain lightweight nonvisual accessibility elements; test traversal from first to last node while most nodes are culled.

- **Major — BRD-20, §9.2:** The product accepts 10,000 nodes and 20,000 edges, but the spike covered 2,000 cards and 2,796 always-mounted SVG paths only in the simulator. There is no memory, input-latency or real-device evidence. **Fix:** cap L2 at the proven size or implement edge culling/tiling and a spatial index; force List view when a device budget is exceeded.

- **Major — SYNC-2/4, §9.3:** The unsandboxed helper can read the user’s account, yet authorization is described only at the TLS layer. Manifest paths, symlinks, Unicode/case collisions, traversal, protocol length limits and helper-control IPC are unspecified. **Fix:** sandbox the helper with security-scoped pin grants where possible; never accept client-supplied filesystem paths; validate destinations component-by-component; bound every frame; authenticate app/CLI IPC using audit-token code-signing checks.

- **Major — SYNC-4:** Per-file atomic swaps do not produce an atomic pin. A page may update before its scripts/images, and tombstone retention, sequence compaction and manifest-ID mismatch behavior are undefined. **Fix:** transfer a complete pin generation into staging, verify it, then atomically switch the generation; use one durable monotonic sequence per pin, full reconciliation on ID mismatch, and retained tombstones until acknowledged.

- **Major — SYNC-5:** iOS does not guarantee that `beginBackgroundTask` finishes the current file or that a continued task starts or survives. The requirement promises both. **Fix:** promise safe pause and resume, not completion; handle submission denial, expiration and cancellation, preserving `.partial` files and reporting “Paused until Linen is open.”

- **Major — SYNC-3, IOS-6:** Dependency closure is missing. Pinning one HTML/Markdown/board file does not say which adjacent assets travel; Files/AirDrop generally grants a single file, not its siblings. **Fix:** make folders/packages the L2 pin unit, or compute and preview a bounded transitive dependency manifest with explicit missing/outside-root results.

- **Major — Goal 4, IOS/SYNC:** Mirrored files may enter iCloud device backup even though Linen uses no iCloud entitlement. **Fix:** mark the mirror and partial-file roots excluded from backup and apply Complete File Protection; test both resource values after installation and replacement.

- **Major — EXP-5/8:** “No font file goes into any PDF” is false: the measured successful path embeds Geeza Pro and Helvetica; only Thmanyah is outlined. PDFKit extraction also does not prove selection geometry, reading order, duplicates or accessibility. **Fix:** say “no Thmanyah font data”; test selection boxes, mixed-direction order and VoiceOver in Preview plus Acrobat/Chrome before claiming selectable text.

- **Major — EXP-6, IOS-7:** A 16,384² RGBA PNG needs roughly 1 GiB before encoder overhead and is unsafe on iPhone. **Fix:** impose a total-pixel/memory budget per device, tile or stream encoding on Mac, and offer scaled or section export on iPhone.

- **Major — CLI-1–6, §9.2:** Running arbitrary pages in a headless WKWebView gives agents executable content without defined sealing, time/memory limits or authenticated helper IPC. `check` also cannot prove what dynamically generated references will do. **Fix:** never run page scripts for `check` or `layout`; run `shot/export` in the exact sealed configuration with deadlines and a crash circuit breaker; describe page checking as static literal-reference checking only.

- **Minor — BRD-8:** “Text never renders under 6 px” conflicts with “only the transform changes mid-gesture”; zooming out necessarily passes below the threshold before rest. **Fix:** qualify the limit as post-settle or hide text before scaling crosses it, and sample continuously during gestures.

- **Minor — CLI-3 and Obsidian test:** Rewriting into a fixed canonical order cannot also guarantee that the diff shows only moved fields. The round-trip fixture includes missing edge sides that Obsidian is expected to add, contradicting “only the moved card.” **Fix:** patch numeric fields syntax-preservingly, or admit first-run normalization; expect added sides explicitly.

### Scope and milestone corrections

- **Major — §6, §9.4, §12:** The current project defines only the Mac app and Quick Look; there are no iOS, helper or CLI targets, and the existing renderer is a mature note renderer rather than a board framework ([project.yml](/Users/hatim/Developer/Satr/project.yml:25), [page.js](/Users/hatim/Developer/Satr/Renderer/page.js:1)). For one person, move BRD-11/13/14/19, live board/page thumbnails, BLK-4–10, background refresh/continued tasks, iPhone export, and CLI `export/pin/status` to 2.x. Keep L2 to core boards, List view, essential blocks, sealed pages with an honest security posture, foreground Wi‑Fi/AWDL sync, and Mac export.

- **Major — S2/M7/M10/M11:** “Answered with evidence” lets a failed spike exit successfully; p95 frame time permits 5% visibly dropped frames; M10 extraction misses bad selection; M11 is simulator-led despite every serious risk being device-only. **Fix:** give S2 explicit go/no-go thresholds; measure dropped-frame ratio, p99/max hitch, input latency, memory and jetsam; require real-iPhone page/performance tests at M11; make PDF visual selection and reading order release gates.

- **Major — sealed-page and link tests:** A witness on selected ports cannot detect Internet/IPv6 traffic, OS/app launches, clipboard/file access or new APIs. Hash equality does not prove absence of stale extra files or pairing resistance. **Fix:** capture all interfaces and DNS, verify filesystem and process side effects, compare complete mirrored path sets, and test pairing races, expiry, replay, wrong certificates, downgrade refusal and identity rotation.
