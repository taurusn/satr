# Satr PRD round 1, Codex

## Review verdict

The product direction is strong, but the PRD is not implementation-ready. Four issues can invalidate the launch architecture; several requirements are contradictory or cannot currently be tested.

1. **Blocker — §9 / PERF-1.** DOMPurify is DOM-only and therefore cannot run directly inside a Web Worker. Sanitizing and posting arbitrary HTML “in chunks” also breaks constructs spanning chunks—reference links, lists, tables, footnotes—and can create unsafe intermediate DOM. [DOMPurify describes itself as DOM-only](https://github.com/cure53/DOMPurify). **Fix:** lex/parse the entire document in the worker, return a token tree, and sanitize/render top-level nodes on the web-content thread. Define first-screen latency separately from complete rendering.

2. **Major — §9 / PERF-3.** The existing renderer is architecturally opposite to the plan: Markdown is embedded in generated HTML and every reload calls `loadHTMLString`, destroying the page, JS state and scroll position ([DocumentWindowController.swift](/Users/hatim/Developer/Satr/Sources/Satr/DocumentWindowController.swift:199), [Renderer.swift](/Users/hatim/Developer/Satr/Sources/Satr/Renderer.swift:27)). **Fix:** make M0 explicitly replace this with one static shell loaded once, then send source and metadata through a versioned bridge.

3. **Major — LIVE-2 / §9 place keeping.** A heading-path-plus-text-hash key is not stable: editing the block changes the hash; duplicate paragraphs collide; one large list may be a single top-level block. “Within one line” is impossible when the anchor itself is deleted or reflowed. **Fix:** combine heading lineage, normalized prefix/suffix, neighboring fingerprints and an in-block text/geometry offset. Specify deterministic fallback and tolerance for deletion, font/image reflow, RTL and zoom.

4. **Major — LIVE-1, LIVE-4 / §9 watching.** A vnode source follows the opened inode, not a replacement at the same pathname; directory events require restatting and rearming. `NSFilePresenter` helps only with coordinated writers, and the current presenter handles change but not move/deletion. Apple recommends coordinated reads when reacting to presenter changes. [Apple file-presenter guidance](https://developer.apple.com/documentation/foundation/nsfilepresenter/presenteditemdidchange%28%29). Also, a 150 ms guarantee conflicts with four-per-second coalescing. **Fix:** directory watch + file identity checks + rearm, coordinated stable reads with retry, and separate “first notification,” quiet-period and maximum-rate targets.

5. **Blocker — SAFE-1–4 / current code.** Current CSP permits HTTP(S) images/media, `file:`, and all inline scripts/styles ([reader.html](/Users/hatim/Developer/Satr/Resources/reader.html:6)); DOMPurify enables unknown protocols; native code silently opens arbitrary file URLs ([DocumentWindowController.swift](/Users/hatim/Developer/Satr/Sources/Satr/DocumentWindowController.swift:171)). Thus every present safety promise is presently false. **Fix:** treat security replacement as M0, not M6: deny all network subresources, allowlist navigation schemes, and implement permission prompts before feature work.

6. **Blocker — SAFE-2 / `satr-local`.** The current handler ignores `rootURL` for authorization, accepts absolute and `file://` paths, permits `..`, and loads the entire file into memory ([DocumentWindowController.swift](/Users/hatim/Developer/Satr/Sources/Satr/DocumentWindowController.swift:306)). Merely resolving symlinks then comparing string prefixes remains susceptible to prefix mistakes and check/open races; Apple recommends descriptor-based operations and `O_NOFOLLOW` for hostile paths. [Apple secure-file guidance](https://developer.apple.com/library/archive/documentation/Security/Conceptual/SecureCodingGuide/Articles/RaceConditions.html). **Fix:** component-wise containment, descriptor-based open/revalidation, regular-file and MIME allowlists, byte limits, cancellation and byte-range streaming.

7. **Major — REN-9 / SAFE-3.** “No style that reaches outside its element” is not provided by DOMPurify; it does not sanitize CSS semantics. `position:fixed`, overlays and remote `url()` remain possible when style attributes/tags are allowed. **Fix:** strip document-authored CSS at launch. If later required, add a real CSS parser with property and URL allowlists plus containment.

8. **Major — §6.11 missing requirement.** No limits exist for document size, nesting, data URIs, media, Mermaid complexity, KaTeX expansion or pathological highlighting. A document can exhaust memory or hang the WebContent/Quick Look process without executing script. **Fix:** specify byte/node/depth/diagram/math limits, time budgets, cancellation and WebContent-process recovery.

9. **Major — SAFE-3 / CSP hashes.** The current inline script contains per-document base64, so its hash changes every reload. Worker creation additionally needs an explicit `worker-src`. WebKit hashes exact inline content. [WebKit CSP guidance](https://webkit.org/blog/6830/a-refined-content-security-policy/). **Fix:** keep all document data out of HTML, hash only immutable renderer code, add `worker-src`, `base-uri 'none'`, and test the effective policy in WebKit—not only generated text.

10. **Blocker — QL-1 / §11 Quick Look.** The PRD commits to a WKWebView renderer before the spike answers whether that design meets sandbox, latency and local-asset requirements. Apple permits ad-hoc signing for extension testing when all targets use the same method, but non-Developer-ID distribution requires explicit Gatekeeper override. Extensions are separately sandboxed; sibling-image access cannot be assumed. Apple provides static HTML previews with CID attachments specifically for linked resources. [Extension signing](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/ExtensionCreation.html), [Quick Look attachments](https://developer.apple.com/documentation/quicklookui/qlpreviewreplyattachment). **Fix:** spike view-based WKWebView against data-based static HTML; test ad-hoc, Personal Team and intended release signing separately.

11. **Major — §11 bundle size.** Lazy loading reduces startup cost, not installed size. The current Mermaid file is already 3.4 MiB; Shiki’s grammars/WASM and KaTeX fonts also affect Quick Look RSS and cold start. **Fix:** set per-component compressed/uncompressed/RSS budgets. Prefer a custom highlight.js build unless Shiki wins measured fixtures; configure KaTeX `trust:false` and expansion limits.

12. **Major — OPEN-1.** “Stays the default opener” is neither enforceable nor respectful of user choice, especially for all plain text. `LSHandlerRank` only declares eligibility. **Fix:** Markdown may offer an explicit “Make Default” action; register `.txt` as an alternate viewer and never silently reclaim either association.

13. **Major — OPEN-7.** Windows-1256-first detection will misdecode Western legacy files as Arabic; Latin-1 may never be chosen reliably. **Fix:** strict BOM/UTF validation, confidence-based detection with an explicit encoding override, and fixtures for CP1252, CP1256 and malformed input.

14. **Major — REN-1, REN-2, REN-11.** “GFM” plus GitHub footnotes, Obsidian syntax and raw HTML is not one defined dialect. Marked versions/extensions can produce different output. `.mdx` JSX will not reliably remain literal text. **Fix:** pin a dialect/version and precedence with golden DOM fixtures. Move MDX to Tier 1 unless implemented by a dedicated tokenizer.

15. **Major — VAULT-2.** “Shortest path wins, case-insensitive” is insufficient for duplicate names, aliases, case-sensitive volumes and renamed targets, so “same as Obsidian” is untestable. **Fix:** define every tie-break and ambiguity state; create generated duplicate/case/alias fixtures and record Obsidian’s result as the oracle.

16. **Major — OPEN-2 / VAULT-1 / architecture.** The distribution and main-app sandbox model is unspecified. A sandboxed app cannot restore arbitrary files or scan a vault after relaunch without persistent security-scoped folder bookmarks. [Apple sandbox guidance](https://developer.apple.com/documentation/security/accessing-files-from-the-macos-app-sandbox). **Fix:** decide App Store versus Developer ID in spike S, then specify bookmark acquisition, stale-bookmark recovery and revoked access.

17. **Major — §4 and §10.** “First readable,” “renders correctly,” “no errors,” “VoiceOver pass” and single-run timings are not acceptance criteria. **Fix:** define signpost endpoints, cold/warm state, p50/p95 over repeated runs, baseline/peak RSS, semantic golden output and screenshot tolerances.

18. **Major — accessibility missing.** The current whole article is `aria-live="polite"`, so live reload may reannounce the document. Selection, keyboard focus and VoiceOver position preservation are absent. **Fix:** remove document-wide live announcements; require focus/selection preservation, rotor headings, table semantics, link labels, Full Keyboard Access and reduced-motion/contrast tests.

19. **Major — tiers.** Launch scope is too broad for the safety and live-reload work. **Fix:** move MDX, audio/video/PDF embeds, LIVE-3 change visualization, OPEN-4 and VAULT-3 backlinks to Tier 1. Keep Markdown/images, find, outline, link following, place-preserving reload, Arabic content, print and Quick Look at launch. Promote signing, sandbox access, accessibility and resource ceilings into launch gates.

20. **Major — §12–13 exit tests.** “Corpus test runs,” one agent rewrite, screenshots that “match,” backlinks compared with grep, and “Quick Look in Finder” miss semantic errors, ambiguous links, watcher races, provider conflicts and clean-install signing. **Fix:** require golden DOM/screenshot tests; save matrices covering rename/delete/recreate/partial writes; adversarial URL/CSP/network tests; and Quick Look tests after clean install, extension registration reset and host relaunch.
